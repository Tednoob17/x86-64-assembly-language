0 - Why Assembly?

0.0 Why Assembly?

We choose assembly to provide a clear introduction to low-level programming and to explain how computers work. Understanding assembly helps with debugging, reverse engineering, vulnerability research, and writing performant low-level code. It also bridges the gap between beginners who rely on copy/paste and experienced engineers who understand system behaviour.

This material is intended to give readers a solid foundation so they can adapt to changing technologies.

1 - Assembly and Low Level

1.0 Assembly and Low Level

Assembly language is a low-level, machine-specific language. Each processor family (here x86-64) uses its own instruction set. High-level languages are translated into assembly, which the processor executes.

Studying assembly improves algorithmic thinking and debugging skills because it requires attention to detail and a deeper understanding of system resources such as memory and registers.

Assembly knowledge is useful in systems programming and security (race conditions, concurrency bugs, reverse engineering).

1.1 History and background

x86-64 (also called AMD64 or x64) is a 64-bit extension of the x86 instruction set. It was introduced by AMD (Opteron) in 2003 and added support for 64-bit operands, extended registers, and paging features.

Readers will benefit from prior exposure to C, C++, or Java and a basic understanding of Linux and the command line.

2.0 Architecture Overview

2.1 Components

A computer contains a CPU (Central Processing Unit), RAM (main memory), storage (SSD/HDD), and I/O devices (keyboard, mouse, display). Buses connect these components and carry data, addresses, and control signals.

CPU

The CPU contains a Control Unit (CU), an Arithmetic Logic Unit (ALU), and registers. The CU orchestrates data movement and instruction fetching; the ALU performs arithmetic and logical operations.

Registers and memory

Registers are small, fast storage locations inside the CPU used for computation. The rsp register points to the top of the stack, rbp is typically used as a frame/base pointer, and rip holds the address of the next instruction.

The architecture is little-endian: the least-significant byte of a multi-byte value is stored at the lowest memory address.

Memory layout

Typical process memory layout contains sections such as .text (code), .data (initialized data), .bss (uninitialized data), heap (dynamic allocation), and stack (local data and call frames).

2.2 Data sizes

Data sizes (byte, word, double-word, quad-word) determine the range of representable values. For example, a 1-byte (8-bit) unsigned value ranges 0–255; a signed byte ranges -128–127.

2.3 Registers overview

The x86-64 architecture provides general-purpose registers (e.g., rax, rbx, rcx, rdx) and SIMD registers (xmm0–xmmN) for floating-point and vector operations.

3.0 Data Representation

Data representation describes how information is stored. Different types (integers, floating-point, characters) use different encodings.

3.1 Integer representation

Computers represent numbers in binary. The number of bits determines the range: 8 bits → 256 values (0–255 unsigned, -128–127 signed). Larger types (16-bit word, 32-bit double-word, 64-bit quad-word) increase the range.

Two’s complement is the common representation for signed integers: invert the bits (one’s complement) and add one.

3.2 Floating-point representation

Floating-point numbers follow the IEEE 754 standard. A 32-bit single-precision value uses a sign bit, an 8-bit biased exponent (bias 127), and a 23-bit fraction.

3.3 Characters and strings

Characters map to numeric codes (ASCII, Unicode). Strings are sequences of bytes, often terminated by a NUL byte in C-style strings.
